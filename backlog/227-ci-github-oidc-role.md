# [ci] CloudFormation stack for a GitHub OIDC deploy role
**What:** Add `infra/github-oidc-stack.yaml` (new stack, e.g. `fernslop-github`) with the GitHub OIDC identity provider (`token.actions.githubusercontent.com`, audience `sts.amazonaws.com`) and an IAM role whose trust policy only allows `repo:<owner>/<repo>:ref:refs/heads/main` (or a GitHub `production` environment) to assume it, with the permissions `infra/deploy.sh` needs on an existing stack; output the role ARN and document in `infra/README.md` how to deploy it once with operator credentials and which GitHub variables to set.
**Why:** User request part 3 (deploy with a GitHub OIDC role); no such role or provider exists in `infra/` today (only the EC2 `InstanceRole` in `ec2-stack.yaml`), and long-lived AWS keys in GitHub secrets are what OIDC avoids.
**Edge cases:** An account can hold only one provider per URL - make creating it optional (parameter to reuse an existing provider ARN); the `sub` condition must use `StringEquals`/exact match, never a wildcard on the repo, so PRs and forks cannot assume it; `deploy.sh` runs `cloudformation deploy` on `fernslop` with `CAPABILITY_IAM`, which needs IAM write - prefer a CloudFormation service role the GitHub role can only `iam:PassRole` over giving it IAM rights directly; scope ECR push to the `fernslop` repository and `ssm:SendCommand` to the stack's instance/`AWS-RunShellScript`; no access to the backup bucket's dumps; short `MaxSessionDuration`. Only files under `infra/`. Out of scope: none.
