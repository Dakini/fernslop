# [api] Room plants: add, move, remove, mark care
**What:** `POST /rooms/{roomId}/plants`, `PATCH`/`DELETE /room-plants/{id}` and `POST /room-plants/{id}/care`. Each one writes its feed event (`plant_added`, `plant_moved`, `plant_removed`, `care_done`) with the undo payload given in `openapi.yaml`.
**Why:** These are the main garden canvas interactions. The feed events are what undo (008) works from.
**Edge cases:** A new plant is placed at 50/50. Adding a 51st live plant returns 409 `This garden is full (50 plants max)`; soft-deleted plants don't count. An unknown `plant_id` returns 404. Move clamps coordinates to 0–100 instead of rejecting them. A soft-deleted or unknown room plant returns 404 `Plant is no longer in this garden`. Care returns 422 `No <care> data for this plant` when the interval is null or 0. The `restore_plant` payload is a snapshot taken before the change. Every mutation bumps the room's `last_activity_at`. Feed `text` is a fragment such as `added a Tomato`.
