# [ci] GitHub Actions workflow running backend and frontend tests in parallel
**What:** Add `.github/workflows/ci.yaml` (no workflow exists yet) triggered on pull requests and pushes to `main`, with two independent jobs: `backend` (`uv sync` + `uv run pytest` in `backend/`, uv and Python 3.13 as in `Dockerfile`) and `frontend` (Node 24, `npm ci` + `npm test` in `frontend/`), cached on `backend/uv.lock` and `frontend/package-lock.json`. Later issues (#226, #228) add jobs to this same file.
**Why:** User request "CI/CD pipeline" part 1: every change is tested before it can be deployed; `Makefile` targets `test` and `test-frontend` are the local equivalents.
**Edge cases:** Backend default suite uses in-memory SQLite and must not need Docker or secrets (fork PRs get no secrets); pin action versions (by SHA or major tag) and `uv` version to match the Dockerfile; set `permissions: contents: read` at workflow level; add `concurrency` per ref with `cancel-in-progress` for PRs only (never for `main`, see #228); a failing job must fail the workflow, not be `continue-on-error`. Out of scope: none.
