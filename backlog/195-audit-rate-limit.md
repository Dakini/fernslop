# [audit] Per-IP rate limits on writes, with real client IPs
**What:** Limit write requests per client IP (room create/delete, posts, photo uploads, plant/area changes, follows, undo, identify), answering 429 with `Retry-After`; first run uvicorn with `--proxy-headers --forwarded-allow-ips` set to the Caddy container only, so the app and logs see the real client IP. Covers audit 1 (rate-limit bullet), 2 (rate-limit part of third bullet), 8 (rate-limit part) and 13 (last bullet).
**Why:** `audit.md`: one anonymous script can wipe all gardens, fill the disk and flood rooms; today every request appears to come from the Caddy container, so neither limiting nor log forensics can work.
**Edge cases:** Open question for the user: the numbers per endpoint and window. In-app (in memory, single worker, see parked #090) vs. the Caddy `rate_limit` plugin (needs a custom Caddy build); no new Python dependency without asking. `X-Forwarded-For` must not be trusted from anyone but Caddy (spoofing); a school or office behind one NAT IP; reads and `/live` SSE must not be limited the same way; the frontend must show a friendly "slow down" message on 429.
