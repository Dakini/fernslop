# [audit] Stop unposted photos from filling the disk
**What:** Schedule `python -m app.photo_cleanup` on the deployed stack (systemd timer or cron in the user-data, or a compose service) with a shorter default age than 24 h, and add a global photo storage ceiling: `POST /api/photos` answers 507 when total stored photo bytes exceed a configured limit. Covers audit 2 (second and third bullets; the Caddy body limit is #203, rate limiting #195, object storage parked #205).
**Why:** `audit.md` 2 (High): 5 MB anonymous uploads with no quota and no cleanup running can fill the 20 GB volume shared with Postgres and Docker in a few thousand requests.
**Edge cases:** Cleanup must not delete a photo a user has just uploaded and is still writing a post for (age must exceed a slow compose); identify uploads that are never posted; photos of soft-deleted rooms (#196); the ceiling check must be cheap (no full table scan per upload); Starlette still spools the whole multipart body before the 5 MB check, so the edge limit in #203 is required; friendly UI message for 507.
