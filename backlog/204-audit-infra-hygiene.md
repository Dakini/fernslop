# [audit] Infrastructure hygiene and a real health check
**What:** Pin `ghcr.io/astral-sh/uv`, `node:24-slim` and `python:3.13-slim` by digest in the `Dockerfile`; pin the docker compose version downloaded in `infra/ec2-stack.yaml` and verify its checksum; give each compose service only its own env variables (Caddy gets no DB password or URL); keep `test_*.py` out of the production image; make `/api/health` touch the database (or add a readiness check the deploy script waits on). Covers audit 13 (bullets 1–4) and 14 (third bullet).
**Why:** `audit.md` 13: floating tags and an unverified binary make builds unreproducible and unreviewable, and Caddy holds secrets it does not need; 14: the deploy health wait passes while Postgres is down.
**Edge cases:** Pinned digests need an update routine (note how to bump them); the arm64 (`t4g`) platform must match the pinned digests; a DB-touching health check must stay cheap and must not take the global store lock for long, or the load balancer/SSE checks may flap; the SQLite dev setup must still pass the check.
