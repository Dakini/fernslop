# [audit] Verify JSON body cap, Content-Type check and threadpool routes
**What:** Groom and QA commit `70dd909` "Cap JSON request bodies, require application/json, keep store calls off the event loop" (already implemented, needs grooming + QA): new `backend/app/body.py` (bodies over 64 KB give 413, a non-JSON Content-Type gives 415), every JSON route is now plain `def`, and `/live` calls the store through `run_in_threadpool`. Covers audit findings 4 (app side), 5 and 9.
**Why:** `audit.md` 4: unbounded bodies can OOM the 1 GB instance; 5: async routes ran blocking store calls under a global lock on the event loop; 9: `text/plain` POSTs skip the CORS preflight, so other sites could write through visitors' browsers.
**Edge cases:** `application/json; charset=utf-8` must pass; a chunked body without Content-Length must still be capped; the frontend HTTP service and `openapi.yaml` must agree (415/413 documented); photo multipart is not affected. The Caddy-side limits are #203; the Postgres advisory lock on every read (rest of finding 5) is parked in #206.
