# [garden-delete] API: delete a garden (room) for good
**What:** Add `DELETE /api/rooms/{roomId}` (`deleteRoom`, 204, no actor headers needed) that hard-deletes the room and everything in it in one transaction: room plants and areas (including soft-deleted ones), all feed events (including undone ones), follows, and the stored photos (bytes) that only this room's feed events point at. This needs a new `StoreProtocol` method implemented in both the in-memory `Store` and `SqlStore` (SQLite and Postgres), plus the `openapi.yaml` entry and its "Soft deletes" note. Default decision, unless the user changes it: anyone with the link can delete (no accounts, "anyone can edit any room" in `_docs/lovable-spec.md`), and the confirm dialog in [#160](160-garden-delete-ui.md) is the only guard.
**Why:** Rooms can only be created today, so a test, mistaken or unwanted garden stays on the public index forever. Hard delete, not soft, because undo only exists per feed event inside a room and the feed goes with the room, so nothing could restore it; keeping follower emails and photos of a "deleted" garden would also be a privacy leak. This departs from the "deletes are soft" line in `_docs/lovable-spec.md` and `openapi.yaml`, which only had plants and areas in mind.
**Edge cases:** A second delete, an unknown id and a non-UUID id all give 404 `Room not found`, never 422; a failure part-way leaves the room whole (one transaction, nothing orphaned, also if a post or plant add runs at the same moment: it finishes before or gets 404). A photo also used by another room's post stays; unposted uploads belong to no room and stay for `app.photo_cleanup`; the shared `plants` reference table is untouched. Open `/rooms/{id}/live` streams (`app/live.py`) must be told (`notify`) and then released so `subscriber_count(room_id)` returns to 0, and later calls on its plants/areas/feed events/photo posts/follows give 404 as for any missing room. The index list and `build_digests` (`app/digest.py`) simply stop seeing the room, a digest unsubscribe link already sent still answers "already unsubscribed", and followers are not emailed that the garden is gone. Seeded rooms are deletable too and are not re-seeded on restart.
