# [ci] Build the Docker Compose stack in CI and run integration and e2e tests against it
**What:** Add a `stack` job to `.github/workflows/ci.yaml` (after #225, `needs` both test jobs) that builds and starts `docker-compose.yaml` once, runs integration tests (the backend suite on the stack's Postgres via `FERNSLOP_TEST_DATABASE_URL`, see `_docs/testing-guidelines.md` "Running the backend suite on Postgres", plus a check that `GET /api/health` returns `{"status":"ok"}`) and then the `e2e/` Playwright suite against the same stack via `E2E_BASE_URL`, and always tears it down.
**Why:** User request part 2; today the stack and e2e (`make test-e2e`, `e2e/README.md`) only run on a developer's machine.
**Edge cases:** Compose `db` publishes no port, so integration needs a CI-only compose override (or a separate Postgres service) - do not change `docker-compose.yaml` behaviour for local use; backend tests empty the database, so run them before e2e or on a separate database; install Chromium with `uv run playwright install --with-deps chromium` matching the `playwright==1.63.0` pin in `e2e/pyproject.toml`; `docker compose down --volumes` in an `if: always()` step so a failure still cleans up; dump `docker compose logs` and upload Playwright traces/screenshots as artifacts on failure; set a job `timeout-minutes`; the CI build is amd64 while production is arm64 (#228), which is acceptable here. Out of scope: none.
