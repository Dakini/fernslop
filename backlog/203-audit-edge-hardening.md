# [audit] Caddy body limits, security headers, HTTPS by default and docs exposure
**What:** In the Caddyfile in `infra/ec2-stack.yaml`, refuse bodies over ~6 MB on `/api/photos` and ~1 MB elsewhere (`request_body max_size`), add a `header` block (`Content-Security-Policy`, `X-Content-Type-Options`, `Referrer-Policy`, `X-Frame-Options`, and `Strict-Transport-Security` when on HTTPS), make the stack require a domain (HTTPS) by default, and make Swagger/ReDoc configurable so production can turn them off. Covers audit 2 (first bullet), 4 (Caddy part), 12 and 14 (fifth bullet).
**Why:** `audit.md`: oversize uploads are spooled to disk before the app rejects them; there are no security headers; the default path serves device ids and tokens over plain HTTP.
**Edge cases:** Open questions for the user: require a domain for the AWS stack (breaks the quick no-domain try-out path), and disable Swagger in production. The CSP must allow the built SPA (inline scripts from the prerendered shell?), photo URLs and the SSE stream; HSTS only when TLS is on; the dev server and `docker compose` locally must keep working; limits must match the app's 5 MB photo and 64 KB JSON caps (#192) with a little headroom for multipart overhead.
