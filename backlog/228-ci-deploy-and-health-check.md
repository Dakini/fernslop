# [ci] Deploy to AWS from main via the OIDC role and verify /api/health
**What:** Add a `deploy` job to `.github/workflows/ci.yaml` that runs only on push to `main` after all test jobs (#225, #226) pass, assumes the role from #227 with `aws-actions/configure-aws-credentials` (`permissions: id-token: write` on this job only), runs `infra/deploy.sh` to push the arm64 image and roll the existing instance, then checks the stack's `Url` output `/api/health` returns 200 `{"status":"ok"}` with retries and an overall timeout, failing the workflow if not.
**Why:** User request parts 3 and 4; today deploys are run by hand from a laptop with operator credentials (`infra/deploy.sh`, `infra/README.md`).
**Edge cases:** Never deploy from PRs, forks or other branches; `concurrency: deploy-production` with `cancel-in-progress: false` so two deploys never overlap or get cut off mid-roll; `deploy.sh` reads the region from `aws configure get region` (empty in CI) - fall back to `AWS_REGION`; CI must only update an existing stack and fail clearly if `fernslop` does not exist (first deploy stays manual, the `read -p` domain prompt must never run in CI); arm64 image needs QEMU + buildx on an amd64 runner or an arm64 runner; the health check must be independent of `deploy.sh`'s own wait (it may follow a DNS/TLS path, a plain-HTTP stack has no domain) and print the response body on failure; role ARN and region come from GitHub repository/environment variables, not hard-coded; job `timeout-minutes`. The `fernslop-github` stack from #227 is deployed in eu-west-2 and trusts `refs/heads/main`, so the job must NOT set `environment:` (GitHub would then send an environment `sub` and the role would refuse); pass `CFN_ROLE_ARN` from `vars.AWS_CFN_ROLE_ARN`; the change-set ARN in the deploy role's policy is unconfirmed until the first real deploy. Out of scope: proving the new image (not the old container) answers health, moved to [#229](parked/229-ci-deploy-version-check.md); automatic rollback on a failed health check, moved to [#230](parked/230-ci-deploy-rollback.md); applying changed instance files (compose, Caddyfile) stays with [#208](parked/208-audit-apply-to-running-instance.md).
